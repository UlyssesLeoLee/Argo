# UI 与业务用例定义

ID：ARGO-UC-001 · 版本：1.0

## 用户界面模块

**统一输入**：上方六种 Provider 卡片；中部单一 Prompt 和标题；下方按平台显示不同上下文字段；附加模型、仓库、执行节点、文件上传与发送按钮。支持 Ctrl+Enter。左侧主导航提供任务、节点、设置。右侧显示在线节点、任务状态与最近任务。没有无意义的中间标签页。

**Multica**：输入 Workspace ID，可使用「查询 Project」「查询 Agent」「查询任务卡」从目标节点已经授权的本地 CLI 获取 JSON 列表。支持「创建新 Issue/选择已有 Issue」两种模式；已有任务卡会先追加评论再指派到选定 Agent，创建任务卡会将标题与正文映射到 Issue。需要注意评论/指派本身可能触发 Multica 服务端动作；Argo 不控制远程实际 Agent 的工作进度。

**Orca**：输入 Repo ID（可以点击查询仓库），选择 Orca 内部 Agent。调用 CLI 创建新 Worktree，返回操作回执与创建结果。如果 Orca 未运行或 CLI 未在 PATH，任务应失败并记录 stderr；不得伪造成功。

**执行记录**：按状态过滤、查看分配节点与任务 ID、增量事件、取消运行、下载文件。运行日志只显示被实际接收到的内容；状态 `dispatched` 与 `completed` 在视觉和语义上严格分开。

**节点**：展示名称、平台/操作系统、在线状态、注册的 Agent、仓库别名、并发限制与心跳；离线超过 45 秒显示离线，不承诺远端机器实际断电。

**设置**：输入 Admin Token，存储于浏览器 sessionStorage；断开按钮销毁该会话令牌。后续计划使用 Star 的身份代理实现 SSO 与 RBAC，避免直接向浏览器下发高权限控制面 Token。

## 基础交互用例

| UC | 操作 | 前置条件 | 正常结果 | 异常处理 |
|---|---|---|---|---|
| UC-01 | 提交 Claude 任务 | Online Node 具有 claude | queued→running→completed | 找不到 CLI → failed |
| UC-02 | 固定节点执行 | Node B 支持目标 Provider | assigned_node=B | B 不匹配 → 阻止提交 |
| UC-03 | Multica 新建卡 | Workspace、Project、Assignee | CLI 创建 Issue 后 dispatched | 缺必填立即提示 |
| UC-04 | Multica 已有卡 | 已有 Issue ID、Agent | 添加评论、重新指派 | 评论成功但指派失败标记 failed、保留日志 |
| UC-05 | Orca 派发 | Repo ID、内部 Agent | 创建 Worktree/Agent 返回 dispatched | 未运行 Orca → failed |
| UC-06 | 查询 Project/Issue | 节点在线且 Multica 已登录 | 将查询结果填充输入建议列表 | JSON 结构不可识别 → 提示查阅原始输出 |
| UC-07 | 上传文件 | 1~20 个 10MiB 以下文件 | SHA-256 Blob 引用可被 Worker 验证下载 | 重名/超大/哈希异常拒绝 |
| UC-08 | 运行取消 | queued 或 running | 取消请求持久化，Worker 检查终止 | 终态任务返回 409 |
| UC-09 | 下载结果 | 任务已有 Artifact | 身份认证后获取内容 | 404、权限错误明确提示 |
| UC-10 | 开启演示 | URL `?demo=1` | 无付费 CLI 调用的完整交互 | 演示标志持续显式提示 |

## 边界条件

输入标题最多 200 字符，Prompt 最多 120000 字符；只允许作为 argv 单独参数、文件内容，不经过 shell 命令拼接。附加文件名禁止 `..`、斜线，后端再次校验，不能仅依赖前端校验。任务接受后主动跳转执行详情。对 API 失败使用显式错误反馈，不允许静默降级为演示成功。

## 适配 Star 的要求

Argo UI 可作为独立页面；Star 中原则上通过 Next.js 服务端建立 Proxy 并在 Star 无限画布任务卡打开侧栏或新面板，不引入 Star 数据库依赖。Star 任务卡 ID、Argo task ID、Provider run ID 需要三向关联（Provider run ID 为二期增强）。
