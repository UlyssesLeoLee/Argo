# Argo v0.3 要件定义（IPA 形式）

## 1. 业务目标与范围

Argo 是独立 Tauri + Rust 多机 Agent/记忆平台；Star 只是一个可插拔客户与平台目标。目标是让用户在**一个 Agent 选项卡**输入，正确路由到对应机器与平台，同时统一管理可复用的跨 Agent 个人记忆。禁止把不同机器的 RAM/VRAM 说成共享空间。

## 2. 功能要件

| ID | 优先度 | 要件 | 验收 |
|---|---|---|---|
| ARGO-REQ-301 | MUST | 单选 Agent Tab 七种：Claude/Codex/Hermes/Orca/MiniMax/Multica/STAR | 始终只有一个平台的专属表单可见 |
| ARGO-REQ-302 | MUST | 多种输入契约差异化，Multica Workspace/Project/Issue、Orca 仓库/Agent、STAR Project/Ticket | 切换不同 Tab 验证字段正确，不虚构未推出接口 |
| ARGO-REQ-303 | MUST | 文件机器→仓库→路径归为同一目标区，执行机器另起独立组 | 空仓库纯聊天可远程；写仓库同机执行，否则拒绝 |
| ARGO-REQ-304 | MUST | 界面美漫 3 渲 2 元素轻量化、无顶部帆船插画/人物 | 仅细墨线、低饱和奶油色、橄榄绿单主 CTA、辅助金色 |
| ARGO-REQ-305 | MUST | STAR 未推出时使用 `?` 标识，可通过明确配置的 REST 适配器派发 | 未配接口不声称可以执行；回执不等于完成 |
| ARGO-REQ-306 | MUST | RAG 连接器去供应商化，允许多套兼容 HTTPS 接口 | UI 不出现部署商名；服务端可选连接配置 |
| ARGO-REQ-307 | MUST | 个人 Key 驱动智能打标、摘要、结构化、批量改写 | 模型服务固定可信 URL 或运维 allowlist；Key 不落库 |
| ARGO-REQ-308 | MUST | 全库记忆批量统一改写 | 先首批预览 + 数量确认 + 8 条/批 + 进度/取消 |
| ARGO-REQ-309 | MUST | AI 修改可恢复与审核 | SQLite 原版本快照，乐观锁，改写后变 draft 不自动入库 |
| ARGO-REQ-310 | MUST | 数据采集、筛选、分段、关联、来源追踪、归档 | 每条 ID 可追溯来源与 revision，引用要显式 |
| ARGO-REQ-311 | SHOULD | 轻量 Tauri 首屏 | 常驻非关键配置默认收起，至少 1280×800 完整显示主任务 |
| ARGO-REQ-312 | MUST | 独立交付/测试 | 完整代码与 Markdown/XLSX/运行手顺/E2E/Logo 同 ZIP |

## 3. 非功能要件

- NF-01: 不对远端无 TLS 控制面发送 API Key；密钥仅在当前请求内存中，不写本地数据库/日志。
- NF-02: 远端知识片段默认先 draft，再 approve，最后 sync；拒绝无审核直接出站。
- NF-03: 保存前审查范围及复用本地 SHA-256 去重；连接失败不误标成功。
- NF-04: Rust 进程执行时采用 argv 而非 shell 字符串。工作目录隔离只是路径约束，不等于 OS 沙箱。
- NF-05: 跨机控制端默认 localhost + TLS 隧道或私有 VPN，具备认证与幂等重试方案。
- NF-06: 大批处理不持久化：关闭窗口可能中止。可恢复作业和后台 Queue 预留于 v0.4。

## 4. 非目标

透明合并 GPU/CPU 内存、自动读取其他 Agent 私有历史、无审批自动将全部聊天发往云端、在未部署的 STAR 上保证真实任务完成。
