# 跨 Agent 上下文与 RAG 信息治理

## 内容边界

来源：Argo 经用户显式开启 `rag_capture=true` 的任务输入及输出（输入、输出分开归档，已注入的RAG引用文本不重复采集）；用户手工粘贴的文档；通过已授权 Vercel 查询后选择导入的远端记录。**不读取**系统中未获授权的 Claude/Codex 等历史目录；不直接扫描其他程序的私有数据库。

## 分段与筛选

1. 在本地 Controller 接收原文；基础规则脱敏常见 Bearer Token / API Key / Password；人工检查仍是强制步骤。
2. 按 Unicode 字符切成 850 字符上限、110 字符重叠的片段，优先按换行和句号等断开；最多 128 段。
3. 每段保存 `source_key` / `task_id` / provider / project / source_kind / 标签 / SHA-256 指纹。
4. 初始状态 `draft`；按 Agent、项目、状态、关键词筛选；人工修正内容、命名、标签。
5. 人工设置 `approved` 后可本地 RAG 引用或点击云端同步；关联知识使用 `rag_links`，保留来源信息。
6. `archived` 不进入运行时召回；不实际删记录。对敏感删除须由下一阶段加入持久删除/远端删除审计。

## 入库与检索

本地 SQLite 存储 RAG 文本、审查状态及 links；当前本地检索是关键词匹配，不是向量近邻。Vercel Gateway 通过 HTTPS 接收已批准片段并写入用户托管 PostgreSQL；参考 Gateway 有关键词检索端点。已有个人 RAG 若 schema 不同，需要适配远端 API，不可以直接将数据库密钥送给 Tauri 前端。

## 质量与隐私审查清单

- 是否包含账号密钥、访问令牌、公司机密、真实客户信息？
- 该段是否有独立语义，能被其他 Agent 正确复用？
- 是否已经过期、存在错误或与其他片段冲突？
- 是否需要关联前置设计/因果关系，还是应该归档？
- 引用后必须附带来源 ID，RAG 文本仅作为不可信参考资料，不能越过 Agent 的安全策略。

## 删除与生命周期

此版支持逻辑归档，不支持已同步记录的远端级联物理删除；生产使用前应设计删除权、TTL、GDPR/APPI 适配与同步撤回机制。不要把本版本视为完备的个人数据治理系统。
