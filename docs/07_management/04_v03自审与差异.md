# v0.3 自审清单与已知差异

| 范围 | 已实现 | 限制与风险 |
|---|---|---|
| UI | 七平台 Tab、机器路径嵌套、独立执行节点、无顶部船插画 | Tauri 像素级比对待 Windows 真机 |
| STAR | `?` 临时 logo、项目/任务卡字段、受控 HTTPS 适配 | 真实 STAR 还未发布，接口契约需双方协商 |
| MiniMax | 经 Hermes 的 provider=minimax 使用 tool-capable Agent | 需 Hermes 版本兼容、配置了相应凭据；不是官方 MiniMax CLI |
| 通用 RAG | 多连接器配置、UI 不绑定部署平台 | 任意外部 RAG API 的 schema 必须另行适配 |
| AI 预处理 | 用户提供 Key、JSON 校验、预览、变更事务、版本历史恢复 | 大模型输出可能不准确；不能单凭自动审核 |
| 全库批处理 | 逐页扫描 ID、每批 8 条、确认、进度、中止 | 客户端进程持久性不足；目前不支持自动恢复续传 |
| 安全 | 服务端 URL allowlist、CAS、脱敏、可选 RAG 出站 | OS 沙箱、RBAC、严格网络策略、彻底脱敏尚未完备 |
| 校验 | JS 契约、语法、静态和 ZIP 检查 | 本容器无 Rust 工具链和正常浏览器导航能力，Rust/Tauri/E2E 不得写为通过 |

### 后续必须完成

1. 在 Windows 开发机 `cargo test -p argo-runtime`、`cargo tauri dev`，验证真实 CLI 的当前参数。
2. 双机 HTTPS/VPN、租约/心跳、失联重试与 Worktree 目录清理。
3. 用你本人 RAG API 实际结构实现适配，而不是仅改连接 URL。
4. AI 任务后台持久队列、全库快照/恢复、海量数据游标与幂等批处理。
5. STAR 上线后落实双向状态同步与事件签名。
