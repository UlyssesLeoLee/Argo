# Argo 基本设计：部署、界面与边界

ID：ARGO-BD-003 · 版本：1.0

## 交付组件与技术标准

| 组件 | 技术 | 选择理由 |
|---|---|---|
| 控制面 | Rust 2021 / Axum 0.8 / Tokio | 单进程低开销、HTTP API 易嵌入 Star |
| Worker | Rust 2021 / Tokio Child | Windows/Linux/macOS 可移植，低资源常驻 |
| 状态存储 | SQLx 0.8 / SQLite WAL | MVP 无额外数据库服务；避免内存队列丢失 |
| 文件传输 | SHA-256、HTTP Blob、磁盘缓存 | 简单、可校验、按内容去重 |
| UI | 无框架 ES Modules / CSS | Star-independent，不依赖 npm 或构建服务 |
| 对接 Star | Next.js server-to-server REST | Star 权限层不暴露 Argo Worker 秘钥 |
| 观察 | tracing / event tables | 易追踪任务状态 |

## Web 页面结构

`web/index.html` 是一个独立响应式工作台，核心操作严格按「选平台→写任务→选目标与资料→提交→查看结果」排列。使用语义按钮和 label，Ctrl+Enter 快速提交，出错实时反馈。右侧只显示高价值的 Node/Recent Run 数据。任务视图显示日志与 Artifacts，节点视图显示在线状态和并发槽，设置视图保存会话 Token。

| 平台 | 必填 | 可选 | 说明 |
|---|---|---|---|
| Claude | Title/Prompt | model、node、repo、附件 | `claude -p` |

| MiniMax | Title/Prompt | model、node、repo、附件 | `mcode exec` |
| Orca | Title/Prompt、orca_repo_id、orca_agent | node、附件 | CLI 创建 Worktree+Agent |
| Multica | Title/Prompt、workspace_id、assignee、project_id 或 issue_id | node、附件 | 项目/任务卡而非普通终端聊天 |

## 网络与安全边界

浏览器→Controller：默认同源，sessionStorage Admin Token。Controller→Worker 没有推送连接，由 Worker 主动 claim；Worker 只需要主动出站 HTTPS。Controller→第三方 API 没有直接传输，CLI 所在节点自身访问外部服务。远端部署须使用 TLS 或零信任隧道，生产必须更换细粒度授权机制。

## 执行/接收的不同完成语义

- 同步 CLI：若 CLI 退出码为 0，Argo 标记 completed；不等于用户验收通过。
- Orca/Multica：CLI 成功派发，标记 dispatched；下游 Agent 的持续生命周期交由原平台处理。
- 网络/依赖错误：日志与失败状态可见；不使用模拟结果冒充生产运行。
