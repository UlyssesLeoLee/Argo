# ST 系统测试与用户验收

| ID | 场景 | 合格判定 |
|---|---|---|
| ST-01 | 新用户第一次打开 Tauri | 5个主导航、6个平台选项卡、主屏视觉不拥挤 |
| ST-02 | 选择 Multica | 只出现 Workspace/Project/Issue/Assignee，不暴露 Orca 参数 |
| ST-03 | 选择 Orca | 只出现 Repo/内部 Agent 字段，显示 Worktree 派发语义 |
| ST-04 | 文件机器切换 | 仓库选择随机器改变，路径始终附属于文件节点 |
| ST-05 | 任务执行机器 | 与文件选择独立；非法跨机写入明确提示并拒绝 |
| ST-06 | 个人 RAG | 可导入/分段/搜索/按 Agent+项目+状态过滤 |
| ST-07 | 片段治理 | 可编辑/审核/归档/恢复/链接，不自动上传 |
| ST-08 | 云端集成 | 连接用户 Vercel RAG，按需搜索、审核后同步，DB 中记录一致 |
| ST-09 | 并发 Agent | 多个节点同时执行不同 Provider，任务状态和仓库不混写 |
| ST-10 | 异常恢复 | 网络断、Token 过期、同步超时、Controller 重启均有明确反馈 |
| ST-11 | 美漫UI | 线条、分组、色彩心理、阿尔戈号主题一致，低认知负荷 |
| ST-12 | Star 集成 | Star 能提交、查看、授权调用 Argo，不得直接操作节点本机路径 |

通过要求：真实 Tauri 机器运行、真实 CLI、数据库连通性、行为与安全审查全部完成。当前源代码包仅供首版开发和联调。
