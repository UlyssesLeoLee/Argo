# Argo ST 系统/验收测试设计书

ID：ARGO-TD-ST-001 · 版本：1.0

## 系统验收环境

至少两台 Windows 11 或 Windows/Linux 混合集群；部署 HTTPS/Tailscale 通道；每台单独安装 Agent CLI；有测试 Git 仓库、授权测试账号和隔离工作目录。浏览器需至少覆盖 Edge 及 Chrome，移动端可用常见手机宽度进行响应式验证。

| ST ID | 业务场景 | 前置条件 | 预期结果 |
|---|---|---|---|
| ST-001 | 新用户首次连接 | Controller 已启动 | 未认证时无法访问私有资源；连接后显示节点 |
| ST-002 | 统一输入六平台 | 6 适配器版本已认证 | 切换字段符合目标 CLI 语义；无无效必填 |
| ST-003 | 跨 Windows 双机 | 两 Worker 在线 | 能指定 Node B 执行，Node A 不承担该任务 |
| ST-004 | 多 Agent 并发 | 节点 max_parallel=2 | 同一节点最多 2 个 Worker 子任务同时运行 |
| ST-005 | 不同模型并行 | Node A/Codex，Node B/MiniMax | 任务分别运行各自模型，不要求模型相同 |
| ST-006 | Multica 创建任务卡 | 测试 Workspace、Project、Agent | 正确建立 Issue 关联，dispatched 不表示实际完成 |
| ST-007 | Multica 已有任务卡 | 测试 Issue 已存在 | 评论正确写入，再尝试指派 Agent；二阶段错误可见 |
| ST-008 | Orca Worktree | Orca App 和 Repo 可用 | 新 Worktree 与 Agent 正确创建，状态 dispatched |
| ST-009 | Git 文件审阅 | 测试仓库包含变更 | changes.patch 下载后可应用/审核，不改动主工作目录 |
| ST-010 | Cancel/Disconnect | 任务运行中 | 取消与 Worker 断线有明确状态，失联需人工审核 |
| ST-011 | Star 任务卡联动 | Star 已完成服务端鉴权和 Proxy | 同一 Task ID 在 Star 可追踪；不能越权读取 |
| ST-012 | 视觉与键盘 | 移动宽度 375px、桌面 1440px | 无主要控件遮挡；Ctrl+Enter 可提交 |
| ST-013 | 数据恢复 | Controller 正常停止后重启 | SQLite 中任务/节点/事件保留；离线状态正确过期 |
| ST-014 | 安全验收 | 无有效 Bearer Token | 401；不能通过 Star 前端检索 Worker Token |

## 出厂门槛

- 必须先通过 Rust 编译与所有 UT，再通过所有 Must 级 IT/ST 用例。
- 未实现的生产能力（细粒度鉴权、强沙箱、集群高可用）必须显式列入 release blocker，不以演示通过代替。
- 真正付费模型的回归测试需要在用户授权的测试账号下执行并记录成本。
