# E2E 自动化测试设计

## 用例 1：Multica 单 Agent 表单

浏览器打开 `?demo=1` → 点击 Multica → 查看 Workspace/Project/Issue/Assignee → 输入任务 → 文件机器 DEV-01、仓库 Argo、执行 DEV-01 → 提交 → 任务模拟派发。应显示“DEMO”标识且不执行 CLI。

## 用例 2：Orca 配置

切换 Orca → 仓库 ID 和启动 Agent 出现，Multica 字段消失；范围在机器下展示；切换执行节点到 DEV-02 时，仓库文件任务提示阻止。

## 用例 3：RAG 片段管理

个人 RAG → 切换“待审核” → 点击某条→编辑标签→批准→切换“已批准”→从执行页面引用该条→提交任务→任务数据包含 citation；再次进入片段→归档→不出现在可引用集合。

## 用例 4：Vercel Mock

配置 HTTPS mock endpoint、Bearer token，发送已批准片段，验证请求体有 source_key/provider/project/fingerprint/revision。超时或失败不得将状态变 synced。

## 自动化计划

代码包含 `tests/rag.contract.test.mjs` 的可执行 Node 单元契约测试；E2E 的真实浏览器自动执行需要安装 Playwright 和 Chromium，并让浏览器访问本地 preview（本次执行环境的浏览器导航被管理员策略阻止，未完成截图/浏览器自动化验证）。
