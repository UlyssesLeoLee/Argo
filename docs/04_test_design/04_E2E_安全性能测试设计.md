# Argo E2E / 可靠性 / 安全 / 性能测试设计

ID：ARGO-TD-E2E-001 · 版本：1.0

## E2E 主路径

1. 启动 Controller，在本机与另一个节点分别启动 Worker。
2. UI 设置 Admin Token，确认两个节点在线。
3. 分别选择 Codex、Claude、Hermes、MiniMax、Orca、Multica，核验上下文字段随选择切换。
4. 为 Multica 调用 catalog Project/Issue/Agent 并从列表选择真实 ID；创建测试 Issue 后检查其真实归属。
5. 对 Orca 使用仓库 ID + Agent；检查 Worktree 创建。
6. 附加文件，验证 Worker 收到的 SHA-256 与上传一致。
7. 提交固定节点任务，查询日志和状态，下载 changes.patch，确认主工作树未被直接更改。
8. 在第二个任务中触发取消，验证后端状态和本地进程状态。
9. 以错误 Token、错误 Project、不可用 CLI、超大附件、非法路径逐个执行负向测试。

## 故障注入表

| ID | 注入故障 | 正确表现 | 失败判定 |
|---|---|---|---|
| FI-01 | Controller 网络不可达 | Worker 重连、重新注册 | 任务被重复领取或消失 |
| FI-02 | 执行中强制断 Worker | 90 秒后 needs_review | 自动重复创建外部 Issue |
| FI-03 | 同时 10 个 Worker claim | 每任务至多一个占有者 | 多进程执行同一 Task |
| FI-04 | Blob 下载后篡改字节 | SHA-256 不一致而终止 | CLI 继续执行篡改文件 |
| FI-05 | 改造 CLI 返回 1 | failed + stderr | 标记 completed |
| FI-06 | Multica 评论成功、assign 失败 | failed、记录部分副作用 | 自动再次评论 |
| FI-07 | 客户端持错误 Token | 401 | 接受敏感操作 |
| FI-08 | 运行中下发取消 | 子进程被停止，状态 cancelled | 不再停止/状态卡死 |
| FI-09 | Orca CLI 仅成功启动 Agent | Argo 显示 dispatched | 显示 completed |
| FI-10 | symlink 路径攻击 | 不应写出任务受控目录 | 文件覆盖系统关键路径 |

## 安全测试

`SEC-001` XSS：向任务标题和 stdout 注入 HTML/JS，应以纯文本显示。`SEC-002` 路径穿越：附件名 `../../.ssh/id_rsa` 应在客户端和服务端拒绝。`SEC-003` Prompt 特殊字符：`&&`, `;`, `$(...)` 应作为单独数据 argv，不通过 shell 解释。`SEC-004` 权限边界：Worker Token 不得创建任务，Admin Token 不得注册伪 Worker。`SEC-005` 敏感信息：日志不得记录 Admin/Worker Token、第三方 API Key。`SEC-006` TLS：公网入口拒绝明文 HTTP。

## 性能与资源压力测试设计

- `PERF-001` 2 Node × max_parallel 2，批量 20 个模拟任务，检查最多 4 个同时 running。
- `PERF-002` 1000 个任务查询，`GET /tasks` 默认 100、最大 300，页面不冻结。
- `PERF-003` 10MiB Blob 重复上传 100 次应以相同 Hash 返回，最终磁盘不出现 100 份重复内容。
- `PERF-004` 事件 1000 行每个 4KB，检查 seq 单调与 since 分页无重复或丢失（需要实现分页自动拉取）。
- `PERF-005` 进程异常终止与高并发情况下内存/句柄泄漏检测，运行 24h。
