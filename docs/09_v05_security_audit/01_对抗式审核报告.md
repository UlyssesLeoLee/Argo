# Argo v0.5 对抗式代码审核报告（IPA 结构）

**范围**：基于用户已收到的 Argo v0.4.0 真实源代码，不将历史说明作为证明。目标为 Rust/Tauri 2/TypeScript 多机 Agent 平台及个人 RAG。结论：**适合继续开发，不符合正式商用验收标准。**

## 1. 审查方法

- 威胁建模：不受信 Worker、伪造 `node_id`、API 重放、越权文件写入、恶意 Git Patch、AI 批量误修改、恶意模型输出、进程异常退出。
- 红灯：先在 v0.4 上执行 `node --test tests/v05.adversarial.test.mjs`，得到 **7 失败 / 3 通过**，证据见 `reports/RED_v04_regression.log`。
- 绿灯：在 v0.5 修复后执行 `npm run check:all`，**92/92 测试通过**。真实 Git 冒烟及五个安全行为验证通过。证据见 `reports/GREEN_v05_regression.log`。
- 工具限制：环境没有 `cargo` / `rustc`，没有 Windows WebView2；**未完成 Rust/Tauri 编译，未执行真实 HTTP 双机 E2E；不能称已通过 Rust 单测或多机安全测试。**

## 2. 对抗性发现与实际处理

| ID | 等级 | v0.4 发现 | v0.5 修改 | 当前判定 |
|---|---|---|---|---|
| SEC-01 | Blocker | `worker.rs` 反斜杠字符字面量转义错误，阻断 Rust 编译 | 改为 Rust 合法的 `\\` 字符字面量，新增静态回归 | 代码修复，待 cargo 验证 |
| SEC-02 | 高 | 使用节点 ID 作为目录名但允许 `/`、`..` 等 | `safe_node_id` 在 Worker、Controller 注册处双向检查 | 静态通过，Rust 单测待跑 |
| SEC-03 | 严重 | Worker 共用 Bearer，能够冒充任意节点 | 支持 `ARGO_NODE_TOKENS_JSON` 每节点密钥；共享模式仅本机回环地址、显式开启 | 静态通过，跨机联调待跑 |
| SEC-04 | 高 | 租约过期后旧 Worker 仍能发事件、附件、完成状态 | `own` / `renew` / `finish` 要求运行状态及未到期租约 | 静态通过，HTTP 集成待跑 |
| SEC-05 | 高 | AI 预览与应用没有服务端绑定，可绕开预览步骤提交修改 | SQLite 保存 10 分钟预览，单次消费，校验提交内容与预览完全一致 | 静态通过，SQLite Rust 测试待跑 |
| SEC-06 | 中高 | 所有 Worker 可使用共用凭据访问 Blob 接口 | Blob 使用管理员或已注册节点凭据 | 已减轻；细粒度 Blob ACL 仍未完成 |
| SEC-07 | 中 | `ARGO_REPOS` 用 `;` / `=` 分隔，Windows 合法路径歧义 | 改用 `ARGO_REPOS_JSON`，旧格式仅保留兼容 | 静态通过 |
| SEC-08 | 高 | 超过 200KB 的 Patch UI 只显示部分却仍可批准 | 服务端拒绝超过审阅上限或 SHA-256 不匹配的 Patch | 静态通过 |
| SEC-09 | 中 | 指定不存在的或不支持目标 Agent 的执行节点后任务无限排队 | 创建任务时检查在线节点与 provider 可用性 | 静态通过 |
| SEC-10 | 中 | 仓库 Path 含 `;` / `=` 会被错误拒绝 | 与 JSON 映射同步，允许合法绝对路径 | 静态通过 |
| SEC-11 | 中 | 任务附件申报大小与实际 Blob 可不一致 | 校验实际 Blob 大小与申报值一致，限制上限 | 静态通过 |
| SEC-12 | 中 | RAG 连接器重启 Sidecar 失败仍反馈成功 | 返回失败原因，便于操作员修复 | 静态通过 |

## 3. 特别保留的高风险 / 发布阻断项

1. **进程隔离缺失（P0）**：Rust Agent CLI 以执行节点用户权限运行；Git Worktree 只隔离 Git 版本操作，不限制读写其他绝对路径。不能向不可信 Agent/不可信仓库提供高权限主机，应先完成 Windows 限权进程 / Linux 容器及出站网络策略。
2. **Blob 访问控制（P0）**：已支持节点独立令牌，但 Blob 权限仍未绑定任务、节点和短期下载许可；具备节点令牌的受信节点可能访问知道哈希的 Blob。下一版引入 TaskBlobGrant 表与一次性授权 URL；未完成前只允许受信集群。
3. **节点认证升级迁移（P1）**：本机回环可启用共享令牌模式，仅供个人桌面；远端 Controller 必须配置每节点不同的 Token 并通过受保护 TLS/VPN 通道传输。尚未实现 mTLS、证书生命周期及密钥轮换服务。
4. **RAG 批量处理（P1）**：修复后单批次预览有效期 600 秒，消费一次。跨批完整事务、断点续跑和原子全库回滚尚不存在；应保留备份后执行。
5. **AI 提示词注入 / 敏感内容（P1）**：脱敏是 best-effort，不保证识别所有私密信息；AI 预处理需要人工检查，API Key 不进入浏览器持久存储。
6. **Tauri Sidecar 真机（P0）**：Windows exe/MSI、进程退出、后台重启、端口冲突、用户权限和商用签名尚未真实验证。
7. **第三方 CLI 兼容（P1）**：Claude、Codex、Hermes、MiniMax、Orca、Multica、STAR 参数及平台可用性须逐个版本验证；STAR 为未发布接口，占位适配不等于成功执行。

## 4. 交付验收定义

当前“绿色”仅表示 TypeScript、JS 契约与 Git 测试在此环境通过。**未提供可运行 EXE，不宣传生产就绪。** 用户在 Windows 执行 `scripts/red-green.ps1`，再执行 `cargo test -p argo-runtime`、`cargo check -p argo-desktop` 和 `python tests/integration_cluster.py`，均通过后才能逐项签收。
