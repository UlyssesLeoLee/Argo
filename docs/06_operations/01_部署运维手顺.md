# Argo 部署与运维手顺

ID：ARGO-OPS-001 · 版本：1.0

## 先决条件

Controller 机器安装 Rust stable、Cargo、Git（Worker 的 Git Worktree 模式需要 Git）；每个 Worker 安装至少一个第三方 CLI 和本地认证。Windows 11 推荐 PowerShell，Linux/macOS 使用 bash/zsh。首次 Rust 构建需要下载 Cargo crates，允许联网或预先准备依赖缓存。

## 最小启动

```bash
# 在 Argo 仓库根目录
export ARGO_ADMIN_TOKEN='replace-with-unique-random-32-or-more-chars'
export ARGO_WORKER_TOKEN='different-unique-random-32-or-more-chars'
export ARGO_BIND='127.0.0.1:8788'
export ARGO_DATA_DIR='./data'
export ARGO_WEB_DIR='./web'
cargo run -p argo-runtime -- server
```

另开一个终端：

```bash
export ARGO_WORKER_TOKEN='different-unique-random-32-or-more-chars'
export ARGO_SERVER='http://127.0.0.1:8788'
export ARGO_NODE_ID='linux-main'
export ARGO_MAX_PARALLEL='2'
export ARGO_REPOS='star=/home/me/repos/Star;argo=/home/me/repos/Argo'
cargo run -p argo-runtime -- worker
```

本机浏览器打开 `http://127.0.0.1:8788/`，设置 Admin Token。不可直接执行 `.env` 文件或将凭据提交 Git。

## Windows 指令

```powershell
$env:ARGO_ADMIN_TOKEN='replace-with-admin-token-32-characters'
$env:ARGO_WORKER_TOKEN='replace-with-worker-token-32-characters'
$env:ARGO_BIND='127.0.0.1:8788'
$env:ARGO_DATA_DIR='.\data'
$env:ARGO_WEB_DIR='.\web'
cargo run -p argo-runtime -- server
```

Worker 在另一会话设置 Worker Token、`ARGO_SERVER`、`ARGO_NODE_ID`、`ARGO_REPOS='star=D:\source\Star'` 然后运行 `cargo run -p argo-runtime -- worker`。PowerShell 进程重新打开后环境变量可能需重新设置。可以使用 Windows Task Scheduler/服务包装器管理开机启动，但首版尚未提供服务注册命令。

## 公网/LAN 部署注意

默认监听本机环回地址，不允许其他机器直连。跨机器建议 Tailscale 或云端 HTTPS 反向代理（Caddy/Nginx）；如 Controller 必须监听 `0.0.0.0`，应仅在受控内网后启用 TLS 入口、IP 限制及强随机 Token。生产 Star/Vercel 需通过服务端远程访问 HTTPS API；Vercel Function 不是用来承载常驻 Worker 的位置。

## 运维检查

- `GET /health`：Controller 已运行。
- `GET /api/v1/nodes`：使用 Admin Token，确认心跳与已安装 CLI。
- `GET /api/v1/tasks`：检查排队、执行中、异常、needs_review 任务。
- Controller 数据目录：`argo.sqlite` 与 `blobs/`；备份前应保持数据一致性，SQLite WAL 建议使用 SQLite 在线备份 API，不应只在有写入时复制主 db 文件。
- Worker 任务目录：`data/runs/<node>/<task>`；Git detached Worktree 需审阅后使用 `git worktree remove` 清理，**不要**直接删除未审查的补丁。
- 默认系统日志到 stdout/stderr；建议 systemd/Windows 事件代理收集，避免记录令牌。

## 安全事件与恢复

Worker Token 泄露时立即轮换 Controller 与全部 Worker；Admin Token 泄露时立即轮换并审查任务执行日志。掉线任务进入 needs_review 后检查远端第三方任务是否已经提交，避免二次创建相同 Issue。复位不应自动删除用户修改过的 Worktree。
