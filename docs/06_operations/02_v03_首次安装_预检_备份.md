# 运维手顺：安装、预检、回滚、备份

## 新安装

Windows 推荐：安装 Rust stable/MSVC、Git、Node LTS、Tauri 2 对应依赖。用 `scripts/verify-clis.ps1` 核对可用 CLI。复制 `examples/.env.example` 到不提交 Git 的个人配置，设置 `ARGO_ADMIN_TOKEN` 和 `ARGO_WORKER_TOKEN`。启动 Controller 和 Worker，验证 `GET /health` 与节点列表（私有 Bearer）。

## 更新 0.2 → 0.3

先停止 Controller 与 Worker，复制 `data/argo.sqlite`、SQLite WAL/SHM 文件和 `data/blobs`；升级后首启执行新增 `summary` 列与 `rag_ai_revisions` 表的兼容迁移。**禁止手工复制正在被 SQLite 写入的单个数据库文件作为唯一备份**；应使用 SQLite backup API 或停机打包一致数据。

## Key 和连接器

AI Key 在本地 UI 密码字段输入，仅本次操作发送，结束后清空；RAG 连接器的服务端 Token 单独放入环境变量/Secret Manager；STAR 服务器 Token 同理。禁止把真实 Token 放入项目配置示例、测试用例、日志、截图或提交仓库。

## 防止数据误写

- 归属机器、仓库、路径必须一致；V0.3 拒绝跨机对仓库的直接写入。
- Agent 在工作树中执行不等于被 OS 级沙箱隔离，生产须使用 Windows Job/受限身份或 Linux 容器权限控制。
- AI 批量改写时先做 SQLite 一致备份，再预览，确认数量，按批自动生成版本；改写片段仍需重新审核。
- 异常可从片段「版本历史」恢复；远端已同步旧版时，必须单独处理远端覆盖或删除（尚无通用删除协议）。
