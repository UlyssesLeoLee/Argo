# Argo 部署与运维手顺

## 开发环境

Windows 11 + Node 22+ + Rust stable / Cargo（Tauri 2 Windows 构建另需 WebView2、Windows 构建工具），本地工作目录不要放在阻止 exe 运行的盘符。

### 预览 UI

```powershell
cd Argo
python -m http.server 8899 --directory web
# http://127.0.0.1:8899/?demo=1
```

纯演示数据不会执行真实 AI CLI，不会远程同步 RAG。

### 启动 Controller / Worker

```powershell
Copy-Item examples/.env.example .env
# 根据当前环境加载 .env 中的变量；Rust 并不自动读取 .env。
$env:ARGO_ADMIN_TOKEN='change-me-to-a-long-random-admin-secret'
$env:ARGO_WORKER_TOKEN='change-me-to-a-different-long-secret'
$env:ARGO_REPOS='argo=D:\\workspace\\Argo;star=D:\\workspace\\Star'
# Terminal 1
cargo run -p argo-runtime -- server
# Terminal 2
$env:ARGO_NODE_ID='win-dev01'
cargo run -p argo-runtime -- worker
```

`$env:ARGO_WEB_DIR='./web'` 控制 Web 静态服务。Controller 默认绑定 `127.0.0.1:8788`。启动 Tauri 包装层前请保持 Controller 在本机运行，并在本地设置 `ARGO_CONTROLLER_URL=http://127.0.0.1:8788`；跨网用 HTTPS。

### Vercel 接收端

1. 在 Vercel 数据库关联的 Postgres 上运行 `examples/vercel-rag-gateway/sql/001_create_rag.sql`。
2. 部署 `examples/vercel-rag-gateway/`（Next.js 16 参考网关），配置其 `.env.example` 字段。
3. Controller 设置 `ARGO_RAG_UPSERT_URL`、`ARGO_RAG_SEARCH_URL` 与 `ARGO_RAG_API_TOKEN`。
4. 在 Argo 导入→审核→同步；再用数据库查询验证行数和 fingerprint。
5. 对接已有个人 RAG 时，需按其真实路由与 schema 替换示例接收器；不要覆盖现有数据库结构。

### 安全运营

- 不允许公网明文 HTTP；Token 从机密管理或服务端环境变量读取；Worker 主动注册不用开放入站端口。
- SQLite WAL 数据库及 Blobs 应统一备份；备份时使用 SQLite backup API 或停止 Controller。
- 只开放必要仓库的 ARGO_REPOS；CLI 密钥留在对应 Worker 上。
- RAG 入库前人工脱敏复核；异常任务、失败同步、并发冲突和需要审核状态需保留人工处理入口。
